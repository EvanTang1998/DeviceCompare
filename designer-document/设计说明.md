# 灵眸 · 手机对比网站 — 设计说明

> 一句话定位：帮助用户快速、直观地理解两台（或四台）手机有什么区别，而不是做一张参数表。

## 1. 产品定位

- 简洁明快，视觉风格参照 Apple iPhone Compare 页面（不直接复制）
- 核心目标：**用户选手机 → 并排展示关键参数 → 直观看出差异**
- 遵循 MVP 原则：第一版尽可能简单，先验证页面体验

## 2. 页面布局

**Compare 页面（MVP 核心）**

- 顶部：手机产品图（`src/data/devices/` 放同名图片即自动显示，无图回退为占位卡）
- 手机选择：多层下拉框（先选品牌：苹果/小米/华为/OPPO/vivo/一加/荣耀…，再选型号），带搜索框
- 参数区：最左列为参数名称（吸顶吸左），参数按分类显示
- 响应式：桌面/横屏 4 列；手机竖屏一屏约 2 列，容器横向滑动

**后续页面（第二阶段起）**

- 首页：Logo + 热门对比推荐
- 差异点评：参数行旁标注「谁更强」，如电池 Xiaomi 更大、重量 iPhone 更轻，甚至给出各类目的 Winner
- 手机详情页：单机型完整参数

## 3. 参数范围

**核心参数（MVP 已实现）**

| 分类 | 字段 |
|------|------|
| 基本信息 | 发布时间 |
| 芯片组 | 芯片、内存 RAM、存储 ROM |
| 外观 | 长宽高、重量、边框材质、后盖材质、三防等级 |
| 屏幕 | 尺寸、分辨率、PPI、刷新率、最大亮度、形态、面板（OLED/LCD） |
| 电池 | 电量(mAh)、有线/无线充电功率(W) |
| 摄像头(multi) | 传感器型号、像素、光圈、焦段(mm)、传感器面积(inch)、防抖 |

**次要参数（暂未实现，JSON 中无对应字段）**

扬声器；网络（红外、NFC、蓝牙、WiFi、GPS）；系统；震动马达；插口（USB、3.5mm）；蜂窝频段；按键；解锁方式（指纹/超声波指纹/3D 人脸）

## 4. 数据结构与维护

**目录约定（数据与图片分开存放，靠同名 id 关联）**

- 参数数据：`src/data/devices/<id>.json`，一机型一文件
- 产品图：`src/data/images/<id>.png|jpg|webp`，文件名与 JSON 同名
- 文件名（去扩展名）即机型 id，如 `devices/iphone-17-pro.json` + `images/iphone-17-pro.png`；`src/data.js` 自动扫描并按 id 配对，新增机型无需改代码

**文件结构：顶层直接是机型对象，不再用机型名包一层**

```jsonc
{
  "name": "iPhone 17 Pro",   // 页面显示名
  "brand": "苹果",            // 品牌筛选依据
  "release_year": 2025,
  "chipset": { ... },
  "body": { ... },
  "display": { ... },
  "battery": { ... },
  "camera": [ { "type": "主摄", ... } ]
}
```

**字段规范**

- 字段名全英文 snake_case，带上单位后缀：`_mm` `_g` `_inch` `_mah` `_watt` `_mp` `_nits` `_um` `_deg`
- 取值统一用纯中文（如「不锈钢边框」，不夹英文注释），保证跨机型可对比
- 多值字段一律用数组：`ram`、`rom`、`image_stabilization`、`hdr_formats`
- 摄像头按 `camera` 数组存放，`type` 取值限定为「主摄 / 超广角 / 长焦 / 前置」，页面按此分组
- `display.form` 只写「直屏 / 曲面屏」，不加括号补充
- 缺失值用 `null` 或整个字段省略，页面统一显示「—」

**维护流程**

- 新增机型：复制一份现有 JSON 改名填内容 → 放同名图片 → 推送，三步完成
- 数据来源规范：官方规格优先；传感器型号参考第三方拆解（GSMArena / iFixit 等），官方未公开的在文件内如实标注

后续扩展：手机数量验证体验后（10～20 台），再考虑 API + 数据库（Phase 2）、后台管理平台（Phase 3）。
